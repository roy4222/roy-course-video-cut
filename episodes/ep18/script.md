## 01. 只考一次模擬考，準嗎？

**畫面**：三次模擬考成績差很多；只看一次可能剛好考到會的題目  
**講義**：PART03 p170–171

- [0:26] 想像你要估計自己的實力，只考了一次模擬考，八十五分。這個分數準嗎？
- [0:35] 不一定。可能剛好考到你最熟的章節。換一份卷子，也許只剩七十分。
- [0:43] 比較可靠的方法，是多考幾次不同的卷子，再看平均。如果三次是八十五、七十、七十六，平均大約七十七，這才比較接近真正的實力。
- [0:58] 評估模型也是一樣。只切一次驗證集，分數可能看運氣。今天要學的「交叉驗證」，就是讓模型多考幾次、每次換一份考卷。

## 02. 驗證誤差也會「太樂觀」

**畫面**：講義 p169：同一份驗證集反覆用來挑模型 → 模型慢慢適應驗證集 → 驗證誤差低估泛化誤差  
**講義**：PART03 p169

- [1:15] 先講一個容易被忽略的問題。挑模型和超參數的時候，我們會反覆使用同一份驗證資料。
- [1:25] 試了一百種設定，每次都看驗證成績，挑最高的那個。久而久之，選出來的模型，就會慢慢「適應」這份驗證資料。
- [1:37] 就像同一份模擬考，你考了十次，最後一次一定考很高。但那是因為你記住了這份卷子，不是實力真的變強。
- [1:49] 所以講義說：驗證誤差可能會低估真正的泛化誤差，這叫「選擇偏誤」，selection bias。驗證成績，不能直接當成最後的成績來報告。

## 03. 方法一：Holdout 保留法

**畫面**：講義 p170：隨機切成兩份互不重疊；訓練多 → 學得好，測試多 → 評估穩；重複 Holdout 降低運氣成分  
**講義**：PART03 p170

- [2:04] 最簡單的方法叫 Holdout，中文叫保留法：把資料隨機切成兩份，互不重疊。一份拿來訓練，另一份「保留」起來，拿來評估。
- [2:20] 切的比例是個取捨。訓練的部分多一點，模型學得比較好；評估的部分多一點，分數比較可靠。常見的是八比二。
- [2:35] 缺點是：只切一次，結果就看這一刀切得好不好，有運氣成分。
- [2:42] 改良的方法是「重複 Holdout」：用不同的隨機種子，切好幾次，每次都算一個分數，最後取平均。隨機種子，就是決定「怎麼亂切」的一個號碼，號碼一樣，切法就一樣，可以重現。

## 04. 方法二：K-fold 交叉驗證

**畫面**：講義 p171：分成 K 份，每次 K−1 份訓練、1 份驗證，輪到每一份都當過驗證；10 筆資料 5-fold 輪替動畫  
**講義**：PART03 p171

- [3:03] 先講一個生活比喻。班上分成五個小組，每次讓其中一組當考官出題，其他四組來考。
- [3:14] 輪五次，每一組都當過一次考官。最後把五次的成績平均，就不會只看某一組的題目。
- [3:24] 這就是 K-fold 交叉驗證。K 是一個數字，代表要把資料切成幾份，每一份叫做一個 fold，中文可以叫「折」。
- [3:38] 我們用十筆資料、K 等於五來看。十筆資料切成五份，每份兩筆。
- [3:47] 第一輪，第一份當驗證，其他四份拿來訓練，算出一個誤差。
- [3:54] 第二輪，換第二份當驗證。就這樣輪下去，一直到第五份也當過驗證為止。
- [4:02] 每一筆資料都剛好當過一次驗證，也都當過四次訓練。最後把五個誤差平均，就是 K-fold 的結果。
- [4:13] 講義說，常見的 K 是五或十。K 越大，每次訓練用的資料越多，但要訓練的次數也越多，比較花時間。

## 05. 重複 CV 與分層 CV

**畫面**：講義 p172：一次 K-fold 仍依賴一種切法 → 重複 CV；分層 CV 保持類別比例；同時報告平均與變異  
**講義**：PART03 p172

- [4:27] K-fold 已經比只切一次穩多了。但是講義提醒：一次 K-fold，還是只用了「一種切法」。
- [4:36] 所以可以換一個隨機種子，重新分組，再做一次 K-fold，這叫「重複交叉驗證」，repeated CV。
- [4:45] 第二個改良，叫「分層交叉驗證」，stratified CV。比喻是：分組的時候，讓每一組的男女比例都跟全班一樣。
- [4:56] 放到分類問題，就是讓每一個 fold 裡，正類和負類的比例，都跟整份資料一樣。
- [5:03] 類別很不平均的時候，這一點特別重要。
- [5:06] 最後，報告結果時，不要只給平均，也要給變異，也就是分數上下跳多少。我們實際用五個不同的種子切資料，同一個模型的準確率，最低百分之七十九點二，最高百分之八十五點八。
- [5:23] 所以分數差一兩個百分點，不一定代表模型真的比較好。

## 06. 用 CV 選超參數

**畫面**：講義 p173–174：候選值 → 同一組 folds 評估 → 選平均最好 → 用全部訓練資料重練 → 測試集一次。scikit-learn 實際結果：600 筆模擬資料，480 訓練＋120 測試，3-fold CV 比較 max_depth 2、5、20  
**講義**：PART03 p173–174

- [5:30] 交叉驗證最常見的用途，就是挑超參數。講義的步驟有四步。
- [5:37] 第一步，先列出幾個候選值。第二步，每一個候選值，都用「同一組」 folds 來評估，這樣比較才公平，就像大家考同一份卷子。
- [5:50] 第三步，選平均驗證誤差最小的那一個。第四步，用選到的設定，拿「全部」訓練資料重新訓練一次。
- [6:01] 我們實際跑一次。六百筆模擬資料，先留一百二十筆當測試集，剩下四百八十筆做三折交叉驗證，比較最大深度二、五、二十。
- [6:15] 深度二，三折的誤差平均是百分之二十三點三，太簡單了，學不夠。
- [6:23] 深度二十，平均是百分之二十五點六，太複雜，開始背答案。
- [6:29] 深度五最好，平均百分之二十點零。注意看，深度五在三個 fold 裡，每一折都比深度二十好，這樣的結論比較可靠。
- [6:40] 選好深度五，再用四百八十筆全部重練，最後在測試集上只算一次，誤差是百分之十七點五。

## 07. 一般 CV 為什麼還不夠？

**畫面**：講義 p175–176：同一組 CV 結果同時用來調整與報告 → 過度樂觀；需要額外的評估層  
**講義**：PART03 p175–176

- [6:52] 現在問一個進階的問題。剛剛深度五的三折平均誤差，可以直接寫進報告，當作模型的真正表現嗎？
- [7:04] 講義說：不太行。因為同一組 CV 的結果，同時被拿來「挑」設定，又被拿來「報告」成績。
- [7:15] 比喻是：同學自己出題、自己改考卷，再挑考最好的那一份來報告。分數好看，但不公平。
- [7:25] 挑出來的設定，本來就是針對這幾個 folds 最佳化過的，所以報告的 CV 成績，可能過度樂觀。這就是選擇偏誤，換了一個地方出現。
- [7:40] 講義的整理很好記：一般 CV 回答的是「哪一組設定在目前這些 folds 上最好」；但它沒辦法完全回答「整套挑選的流程，用在新資料上會有多好」。
- [7:56] 要回答第二個問題，就需要再多一層評估。這就是下一個主角：巢狀交叉驗證。

## 08. 巢狀交叉驗證 Nested CV

**畫面**：講義 p177–178：外圈 K-fold 留出外層測試折；內圈在外層訓練資料上再做 CV 選超參數；外層測試折不能參與內圈調整  
**講義**：PART03 p177–178

- [8:07] 巢狀，就是一個套一個，像俄羅斯娃娃。巢狀交叉驗證，就是在交叉驗證「裡面」，再放一個交叉驗證。
- [8:20] 比喻是學校選拔代表隊。校內先辦初賽，選出最好的選手，這是「內圈」。
- [8:29] 然後，派去參加一場校內從來沒看過題目的校外比賽，看這套選拔方法到底準不準，這是「外圈」。
- [8:39] 對應到模型：外圈先把資料切成 K 份，每次留一份當「外層測試折」，先鎖起來不碰。
- [8:48] 內圈只用剩下的外層訓練資料，再做一次交叉驗證，從二、五、二十裡挑出最好的深度。
- [8:58] 挑好之後，用這個設定在外層訓練資料上訓練，最後才打開鎖住的那一份，算一個誤差。
- [9:07] 外圈每一份都輪一次，就得到 K 個誤差，平均起來，就是 Nested CV 的結果。
- [9:15] 講義強調：外層測試折一定要獨立，不能參與內圈的調整，分數才不會被選擇偏誤灌水。

## 09. 那最後要用哪一組超參數？

**畫面**：講義 p179–181：不同外圈可能選出不同 p*；Nested CV 評估的是挑選流程；最終設定用全部 development data 做 CV 選出，再訓練、獨立測試一次  
**講義**：PART03 p179–181

- [9:25] 這時候你可能會問：外圈跑了 K 次，每次內圈都挑出一個最好的設定，那最後到底要用哪一個？
- [9:35] 其實，不同的外圈本來就可能挑出不同的設定，例如第一輪挑到深度五，第二輪挑到深度二。
- [9:44] 講義第一百八十頁問：能不能用 Nested CV 決定最佳參數 p 星？答案是：不能，也不需要。
- [9:55] 因為 Nested CV 評估的是「整套挑選流程」，不是某一組固定的設定。
- [10:02] 那最後的模型怎麼做？很簡單：用全部的開發資料，也就是訓練用的資料，再做一次一般的交叉驗證，選出最終的設定。
- [10:14] 接著用這個設定，在全部開發資料上訓練出最終模型，最後拿從頭到尾都沒碰過的獨立測試集，只評估一次。

## 10. Public 與 Private 測試集

**畫面**：講義 p182–183：單次驗證選到 Model 3（0.5）；3-fold CV 平均：Model 1 0.3、Model 2 0.5、Model 3 0.4 → 選 Model 1；反覆用 public test 調整會間接洩漏  
**講義**：PART03 p182–183

- [10:27] 最後一個觀念，來自資料科學競賽 Kaggle。比賽有兩個排行榜：公開榜和私榜。
- [10:36] 你每次上傳答案，馬上能看到公開榜的分數，它只用一小部分測試資料，也就是 public test。
- [10:45] 真正決定名次的，是比賽結束才公布的私榜，用的是另一部分你從沒看過分數的資料，也就是 private test。
- [10:55] 講義的例子是這樣：如果只切一次驗證集，三個模型的誤差是零點九、零點七、零點五，你會選模型三。
- [11:06] 但改用三折交叉驗證，模型一三折的誤差是零點二、零點四、零點三，平均零點三；模型二平均零點五；模型三平均零點四。這次選的是模型一。
- [11:23] 換句話說，只切一次，可能就選錯模型。
- [11:27] 更大的陷阱是：一直看公開榜的分數來改模型，等於把 public test 當驗證集用。公開榜很漂亮，私榜卻掉下去。
- [11:38] 這叫間接的測試資料洩漏：只要測試結果影響了模型開發，這份測試集就不再獨立。

## 11. 交叉驗證下的 ROC 與 AUC

**畫面**：講義 p184–189：K 組驗證結果無法直接得到一條 ROC；三種做法：各折 ROC、平均 ROC、合併折外 ROC；實際計算：3-fold 各折 AUC [0.8252, 0.8715, 0.8408]，平均 0.8458，合併 0.853  
**講義**：PART03 p184–189

- [11:49] 最後是講義的補充：交叉驗證下，ROC 要怎麼畫？複習一下，ROC 是把門檻從高調到低，畫出真陽性率對假陽性率的曲線，曲線下面積叫 AUC。
- [12:08] 問題是，K-fold 會產生 K 組驗證結果，沒辦法直接得到「一條」 ROC。講義給了三種做法。
- [12:19] 第一種，各折 ROC：每一折各畫一條、各算 AUC，再報告平均和變異。講義的例子是零點七八、零點八二、零點八零，平均零點八零。
- [12:36] 第二種，平均 ROC：先在同樣的一排假陽性率上，把每一折的真陽性率對齊、再平均，畫成一條平均曲線。
- [12:48] 第三種，合併折外 ROC：每一筆資料都在它當驗證的那一折，拿到一個分數，叫折外分數。把所有折外分數合在一起，畫一條整體的 ROC。
- [13:04] 要注意：合併的 AUC，不一定等於各折 AUC 的平均。我們實際跑三折，各折 AUC 是零點八二五、零點八七二、零點八四一，平均零點八四六；合併起來卻是零點八五三。

## 12. 作業三：兩種指定流程

**畫面**：講義 p239：80:20 訓練／測試；方法一 8:2 訓練／驗證、換 3 個 random seed 重複；方法二 3-fold CV；seed 依組別號碼  
**講義**：PART03 p239

- [13:25] 好，現在把今天學的，對到作業三。作業三規定要做兩種流程，兩種的第一步都一樣：先把資料切成八十比二十，八十是訓練，二十是測試集，鎖起來最後才用。
- [13:45] 方法一，叫 holdout 加 holdout。訓練的那八成，再切成八比二，八是訓練、二是驗證。
- [13:55] 而且要換三個不同的隨機種子，重複三次，看三次驗證成績的平均。這就是今天講的「重複 Holdout」。
- [14:06] 方法二，叫 holdout 加交叉驗證。測試集一樣先留兩成，訓練的八成改做三折交叉驗證。
- [14:17] 以鐵達尼號的八百九十一筆資料為例：測試集一百七十九筆，訓練七百一十二筆。方法一每次再切出五百六十九筆訓練、一百四十三筆驗證。
- [14:32] 兩種方法都要再換不同的隨機種子重複。講義還規定，種子要依照組別號碼來設，例如第一組用一、十、一百，第二組用二，以此類推。
- [14:47] 第二十集，我們會真的把這兩種流程跑一次。

## 13. 常見誤區

**畫面**：五張紅色警示卡  
**講義**：—

- [14:53] 來看五個常見的誤區。
- [14:57] 第一，只切一次驗證集，就說模型 A 比模型 B 好。差一點點，可能只是運氣。
- [15:06] 第二，把交叉驗證挑超參數時的最佳分數，直接當成最後的成績報告。那個分數偏樂觀。
- [15:16] 第三，先用全部資料做前處理，例如填補缺失值，才切 folds。驗證的那一折已經偷看到答案，是資料洩漏。
- [15:29] 第四，一直看測試集或公開榜的分數來改模型。改著改著，測試集就變成了驗證集。
- [15:37] 第五，類別不平均時，沒有用分層切法，結果某一折幾乎沒有正類，分數亂跳。
